# Лимит памяти, которого не было

Claude Code умеет ограничивать память для команд, которые запускает в shell. В Linux для этого задают `CLAUDE_CODE_TOOL_MEMORY_LIMIT`. Если сборка или тест начнёт бесконтрольно потреблять память, при достижении лимита процесс должен завершиться, а не уронить всю машину.

Я выставил лимит в 300 MB и запустил команду, которая использовала 1 GB. Она завершилась нормально.

## Почему лимит не сработал

Claude Code помещает команды своих инструментов в новую контрольную группу, cgroup, которую создаёт рядом со своей собственной. При запуске из обычной сессии shell или задания cron собственная группа Claude находится внутри `session-N.scope`, а обычному пользователю нельзя создавать там группы.

Поэтому настроить ограничение не удаётся. Единственный след: одна строка в отладочном логе:

```text
tool cgroup: disabled (EACCES)
```

Всё остальное выглядит так, будто ограничение включено. Переменная задана, ошибок нет, а команда выполняется без какого-либо лимита. Защита, которая молча отказывает, хуже, чем её отсутствие: ты перестаёшь беспокоиться.

## Как исправить

Запустите Claude внутри scope, принадлежащего вашему пользователю:

```bash
loginctl enable-linger "$USER"
CLAUDE_CODE_TOOL_MEMORY_LIMIT=12g systemd-run --user --scope claude
```

Тот же пользователь, та же переменная, та же машина. Отличается только способ запуска Claude:

```text
started from an ssh login:        silent failure, parent not writable
started with systemd-run --scope: limit applies, parent writable
```

## Проверка делом, а не настройками

Я не доверяю настройке, пока что-нибудь не упрётся в заданный предел. На Ubuntu 26.04 с systemd 259 я проверил:

- пользовательский менеджер делегирует `cpu memory pids`, поэтому ограничения для отдельных команд доступны обычному пользователю;
- scope с `MemoryMax=200M` и отключённым swap завершил процесс при выделении 400 MB памяти с кодом 137;
- scope с `TasksMax=20` не дал процессу создать 20-й дочерний процесс, выдав ошибку «ресурс временно недоступен», а вызывающий процесс продолжил работу;
- запуск scope занимает около 16 ms, а запуск команды без него занимает менее 2 ms.

Что нужно знать, прежде чем на это полагаться:

- все сессии одного пользователя используют общую группу, поэтому бюджет памяти задаётся на пользователя, а не на сессию;
- переустановка пакета может добавить в ваш путь поиска исполняемых файлов бинарник `claude`, который запускается в обход вашей обёртки, поэтому после обновлений это нужно проверять;
- я не проверял это при запуске от root;
- на macOS и Windows это ничего не делает.

Проверить свою машину можно двумя способами: прочитать `memory.max` изнутри команды shell, которую запускает агент, или запустить что-нибудь с потреблением памяти выше лимита и проверить код завершения 137. Команда `agent-slowdown memlimit --test` из [agent-slowdown](https://github.com/tonydzi/agent-slowdown) выполняет вторую проверку за вас.
