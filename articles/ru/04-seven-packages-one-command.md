# Семь пакетов, и ни один нельзя установить

В октябре я пересчитал свои публичные репозитории: 61. Восемь из них были инструментами, которые я представлял как пригодные для повторного использования: с `pyproject.toml`, примечаниями к выпускам и словом "install" в README. На PyPI каждое из этих восьми имён возвращало 404. Чтобы попробовать любой из этих инструментов, нужно было клонировать репозиторий. Почти никто так не делает ради инструмента, которым ещё не пользовался.

Репозиторий без команды установки похож на дорогу без въезда. На этой неделе я построил эти въезды. Вот что мне помешало: ничего из этого не было в документации, которую я читал.

## Коротко о Trusted Publishing

PyPI может принять выпуск прямо из рабочего процесса GitHub Actions без сохранённого токена. Для этого на PyPI нужно зарегистрировать "pending publisher", указав владельца на GitHub, репозиторий, файл рабочего процесса и окружение. Первый успешный запуск создаёт проект.

Рабочие процессы существовали уже несколько месяцев. На стороне PyPI ничего так и не зарегистрировали, поэтому каждый запуск выпуска завершался ошибкой или пропускался, а в примечаниях к выпуску было написано «опубликовано».

## Четыре вещи, которые меня остановили

**1. По три за раз.** PyPI разрешает иметь не больше трёх ожидающих издателей на аккаунт. Я зарегистрировал три, а на четвёртом получил ошибку: "You can't register more than 3 pending trusted publishers at once." Выход: сначала опубликовать эти три пакета. Как только проект появляется, ожидающий издатель становится обычным и освобождает место.

**2. Имя слишком похоже на чужое.** Имя `claim-check` отклонили: "This project name is too similar to an existing project". Пакет с именем `claimcheck` уже существует. Теперь инструмент публикуется как `claim-check-ci`, а команда, которую вводят пользователи, по-прежнему называется `claim-check`. Это стоит проверить до того, как писать README с предложением выполнить `pip install` для имени, которое вам не достанется.

**3. Переключатель, который я сам и настроил.** Один рабочий процесс завершился с зелёным статусом, но ничего не опубликовал. За несколько месяцев до этого я поставил запуск задания публикации в зависимость от переменной репозитория, чтобы выпуски не показывались красным до настройки PyPI. Потом я об этом забыл. Зелёный статус с пометкой "skipped" у задания публикации выглядит почти как успех.

**4. Вход в аккаунт с истекающим сроком.** Регистрация проходит через веб-форму, для которой нужно войти в аккаунт. Когда у меня впервые всё было готово, сессия в браузере уже истекла спустя шесть дней. Всё, что зависит от входа человека в аккаунт, стоит заканчивать за один присест.

## Что здесь значит «сделано»

Я считал пакет выпущенным, только когда `pip install <name>` работал в новом пустом окружении и показывал версию. Теперь все семь проходят эту проверку:

```bash
pip install agent-slowdown
pip install claim-check-ci
pip install lambda-cloud-mcp
pip install pr-watch
pip install secondop-panel
pip install verbatim-citation-gate
pip install sqlite-graph-memory
```

Проверка по README ещё несколько месяцев назад показала бы, что установить можно все пакеты. До этой недели проверка установкой находила из семи только один.
